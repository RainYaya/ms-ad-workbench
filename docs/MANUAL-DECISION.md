# 手作業 / AI 実行の判定基準

> この文書は「どの step を人がやるか」を決める唯一の基準。
> block の note や実装都合で、勝手に人の作業を増やさない。

## 1. 判断源は手順書

判定の入力は **手順書の行**（`automation/blocks/case-evidence.json` と `v2/data/evidence.js` の `manualSteps`）。

- 手順書に「バッチ実行」「APログ確認」「DBダンプ」「テーブル確認」「メール送信」「OS の保存ダイアログ」「F12 / 開発者ツール」と書かれている → **人がやる**
- 手順書に「画面を開く」「入力する」「選択する」「遷移する」「画面の値を確認する」と書かれている → **AI がブラウザでやる**

`block` は実装。block の note は「mock でどこまで再現できたか」のメモであり、手順書の代わりではない。

## 2. AI がやるもの

- click / fill / select / popup / 画面遷移
- DOM の値・文言・行数・URL の assert
- 画面 HC の取得
- mock では再現できないが、真機の DOM で確認できるもの（`--live` で実行）

## 3. 人がやるもの

- JP1 / バッチ / シェル / コマンド
- APログ / DBログ / DBダンプ / テーブル
- メール送信・メール内リンク
- OS の保存ダイアログ / 印刷 / ファイル配置
- F12 / 開発者ツールでの値削除
- 外部システム側の確認

## 4. mock 代替（人ではない）

- `mock回写`
- `mock簡化`
- `mockはメッセージ枠のみ`
- `mockに帳票/バックエンドが無い`

これらは **真機では AI が assert する**。mock 実行時だけ skip する。
真機で実行するときは `--live` を付ける。

## 5. 例：AZ-110-01-009

手順書の `manualSteps` は **0 件**。したがって手作業は 0 件。

block には次の 3 つの mock 代替 assert がある：

| 行 | 確認 | mock の制約 | 判定 |
|---|---|---|---|
| 17–21 | 保険種類の反映 | mock が値を回写 | AI（`--live`） |
| 22–29 | 募集人の opener 回写 | popup の閉じる処理を簡略化 | AI（`--live`、optional） |
| 54–57 | `MAZG101W047` メッセージ | mock にバックエンドが無い | AI（`--live`、optional） |

以前は「手作業 3 件」と表示していたが、これは誤り。
今は「手作業 0 / mock 3」と表示する。

## 6. 手順外 block 人工

block に `manual` や「非浏览器=真機人工」があり、手順書の `manualSteps` に対応行が無い場合がある。
これは **手順外の実装メモ** として警告に出すが、作業单の人工数には入れない。
手順書に無い作業を現場に押し付けないため。

## 7. 迷ったとき

1. 手順書の行を見る。
2. その行の `type` / `item` / `content` がブラウザで観測できるかを見る。
3. 観測できる → AI。
4. 外部システム/OS/ログ/DB/メール → 人。
5. block の note だけで判断しない。

この順序を変えない。
