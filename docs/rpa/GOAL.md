# GOAL — ms-ad RPA 平台

## 目标（一句话）

把 450 本保险业务手顺书，变成一个**可跑、可改、可查**的 RPA 系统：
每本一个可读文件，跑的时候能停下来人工接管，出错能指回 Excel 行号。

## 为什么

真机第一次跑"惨不忍睹"。根因不是 selector 写错了，是三件事：

1. 出错就关浏览器，看不到现场
2. 一本要跨 10 积木 + 16 selector 文件 + 9 params 文件，改一处穿四层
3. 没有证据链，判断不了"对不对"

## 成功标准（可验收）

### 必须（MVP）

- [ ] 一本手顺（009）从 YAML 跑完 44 步，mock 上 done=44
- [ ] 任意一步失败时，**浏览器不关**，能选 重试/跳过/手填/保留/退出
- [ ] 每个 step 带 Excel 行号，能指回原文
- [ ] 改一个参数值，只改一行，重跑生效
- [ ] 改一个 selector，只改字典一处，所有本生效

### 应该

- [ ] 4 本不同类型（更新系/另一业务线/异常系/批处理）都能编译通过
- [ ] 批处理本被正确识别为"不进浏览器"
- [ ] 有 UI：能选一本、点运行、看进度、失败时停下

### 不做

- 不追求 450 本全绿（mock 绿不代表对）
- 不改 `runner.mjs`
- 不用 playwright（只用 playwright-core + 系统 Edge）
- 不手改 `execution-status.json`

## 关键约束（违反即失败）

| # | 约束 | 原因 |
|---|---|---|
| R0 | **碰到问题先查代码，不许猜** | reference/webapps 是权威，Shift_JIS |
| R1 | 不许猜 selector | 查不到就标 pendingRuntime |
| R2 | 只显示字段不能当输入 | id 为 null 的只能断言 |
| R3 | 流程文件不写 CSS | 否则 450 本各改一遍 |
| R4 | 不许为通过改断言 | 改断言是造假 |
| R5 | 每步必须有 Excel 行号 | 否则无法验证 |
| R6 | 输入值与期望值分开 | 混一起会误报 |
| R7 | 手工配置与生成物分文件 | 否则被覆盖 |
| R8 | 大文件不用 heredoc 写 | 超 8KB 静默截断 |
