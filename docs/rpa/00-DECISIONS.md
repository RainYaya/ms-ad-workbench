# RPA 重构 — 已定的决策

> 这份文档是给"上下文已经清空的我"看的。每条都写清：定了什么、为什么、代价是什么、什么情况下该推翻。
> 最后更新：2026-10-26

## 一句话总结

把手順書 450 本从"积木拼装"改成"1 本 = 1 个可读流程文件"，CSS 从 UI 字典查，真机 DOM 缺失的地方明确标成待办，不猜。

---

## D1. 形态：做成 RPA

**定了什么**：不是"更聪明的批处理"，是可交互、可定制、带预制模板的 RPA。

**为什么**：
- 现执行器一遇错就 `throw` → 关浏览器 → 只剩一行日志。真机上没法 debug
- 一本要跨 10 个积木 + 16 个 selector 文件 + 9 个 params 文件，改不动
- 用户原话："哪怕我手动，应该也可以形成一个自动化的流"

**代价**：要重做数据层，450 本要迁移。

**什么情况下推翻**：如果最终发现真机上流程极其稳定、几乎不用改，那成本就不值。但目前已知有 6 个运行期才能确定的字段，所以不成立。

---

## D2. 技术栈：不改

- Node v24.18.0 + **playwright-core 1.64.1**（不是 playwright）
- `chromium.launch({ channel: 'msedge' })` → 用系统自带 Edge，**不下载浏览器**
- 原因：真机（公司电脑）装不了新浏览器，也没有安装权限

**⚠️ 硬性约束**：所有 mjs 脚本必须放在 `automation/node-runner/` 目录内运行，否则 `playwright-core` 解析不到（Node 按 cwd 找 node_modules）。这次已经踩了 2 次。

---

## D3. 三层结构（不是四层）

```
① 动作层     goto/click/fill/select/check/clickRow/expect/wait/manual   （10 个原子，几乎不动）
② 字典层     ui-dictionary.json + ui-screens.json + ui-aliases.json     （前端变化改这里）
③ 流程层     flows/<CASE>.yaml                                          （一本一个，人和 AI 都改这个）
```

**没有"积木层"。**

**为什么砍掉 252 个积木**：
- 实测 1613 个执行步骤里 **只有 177 步引用 params（10%）**，其余 90% 硬编码（`AHE61` 写死 17 次）
- 所以"一块被 348 本复用"是统计巧合（手顺长得一样），不是真复用
- 125/252 个块只被 1~2 本用 → 是"手顺的化石"，不是积木
- 积木把"动作"和"画面名"绑死，而画面名本身有 10 处对不上前端

**什么该保留**：252 个积木**原样留在仓库**，定位改成"模板片段库"。迁移期间新旧可对照，出问题能退回。

---

## D4. 流程文件：写标签，不写 CSS

```yaml
- row: 24                  # 手順書 Excel 行号，这是证据链
  screen: 募集人検索画面
  do: fill
  部店課支社コード: "{部店課支社コード}"
```

**关键**：`部店課支社コード` 是日文标签，不是 selector。selector 由 `compile_flow.py` 从字典查。

**为什么**：
- 真机上 CSS 会变（尤其是表内动态 name），但日文标签不会变
- 用户能读懂、能改
- 改一处（字典）→ 450 本全生效

---

## D5. 编译器：宁可报错，绝不猜

`compile_flow.py` 对每个 target 分三种结果：

| 结果 | 含义 | 处理 |
|---|---|---|
| `selector` | 字典里有 id | 直接用 |
| `rowfield` | 表内行，有模板 | 生成 `tr:has(td:has-text("值")) input[name=xxx]` |
| `pendingRuntime` | 模板里没有，只能真机看 | **列出来，当待办** |

**绝不做的三件事**：
1. 同名多 id 时不猜（`....` 在 AMA04 有两个：保险种类/募集人，模糊匹配会点错）
2. 模糊匹配要求重叠度 ≥60%（`選択欄` 曾错配到 `選択` 按钮）
3. 不认识的画面名直接报错，带上 Excel 行号

**为什么这么严**：用户今天问题的根源就是"看起来差不多"被当成"对"。这层必须严。

---

## D6. 真机抓取：DOM 只能从真机拿

**定了什么**：`automation/node-runner/capture.mjs`，人手动操作，自动保存每个画面的渲染后 DOM。

**为什么不能"另存为网页"**：
- 前端全部 **Shift_JIS**，手动另存会变 UTF-8 或乱码
- 弹窗存不下来
- 一页一页点太慢

**为什么必须真机 DOM**：
- 实测 6 个待解字段全在"表内动态 name"或"JS 动态插入"处
- 模板里有的是 `th:value` / `[(${...})]`，不是渲染后的样子
- 例：`form['imperfectSearch[' + indexNo + ']']` —— 运行时拼接，静态文件里根本没有

---

## D7. 数据分工

| 文件 | 来源 | 谁维护 |
|---|---|---|
| `ui-dictionary.json` | 前端 HTML 自动提取 / 真机捕获 | **100% 脚本生成**，随时可重建 |
| `ui-rowfields.json` | 代码分析（动态 name）| **100% 人工**，见 P17 |
| `ui-screens.json` | 手顺画面名 → 画面码 | **人工**（真机确认后改 status） |
| `ui-aliases.json` | 别紙说法 → 前端说法 | **人工**（短、明确、可审计） |
| `flows/*.yaml` | 手顺 JSON + AI 阅读 | 人 + AI |
| `reference/webapps/` | 原始前端快照 | 只读，不动 |

---

## D8. 450 本怎么迁移

**不要一次性全做。**

1. 先 1 本（009）跑通全链
2. 再 5 本不同类型（含异常系、批处理），验证普适性
3. 确认格式不改了，再批量生成 450 本

**为什么**：格式一旦返工，450 本全废。先小样本锁定格式。
