# 开发步骤（按顺序做，每步可验收）

> 这份是**施工顺序**。前面都完成了才做后面，不要跳。
> 每一步都写了「做什么 / 验收标准 / 卡住怎么办」。

---

## 第 0 步：真机抓 DOM ✅ 工具已就绪，等你执行

**做什么**

```cmd
cd automation\node-runner
node capture.mjs --url https://真机/AMB/AMA01.html --out capture-1027 --edge
```

手动把 009 走一遍（顺便摸环境），`Ctrl+C`，把 `capture-1027` 发回。

**注意**
- `種目` 必须先选，否则保险种类 `....` 按钮**静默无反应**（源码 `if(selectedIndex<=0) return;`）
- 点了没反应的步骤，记下是哪一步
- 不需要提供任何账号密码

**验收**：`capture-1027/pages/` 里有 10+ 个画面，`.json` 里有 `ids`/`pairs`/`tables`

**卡住怎么办**：如果 node 跑不起来，先确认在 `automation/node-runner` 目录下

## 第 1 步：用真机 DOM 消除 pendingRuntime

**做什么**
1. `python tools/build_ui_dictionary.py --src capture-1027/pages --merge`
2. 对比真机 DOM 和当前字典的差异
3. 把 8 个 `pendingRuntime` 全部确定（row 34/39/42/43/45/48/51×2）
4. `ui-screens.json` 里 25 个 `inferred` → `confirmed`

**验收**：`compile_flow` 的 `pendingRuntime` 为空

**卡住怎么办**：某个字段真机上就是不可操作 → 标 `runtime-resolve` 并在流程里写 `manual`

## 第 2 步：009 在 mock 上跑通全部 44 步

**现状**：`row 14→31` 通过，`row 32` 卡住（点「登録」后 mock 不跳转）

**做什么**（二选一）
- A. 修 mock 路由，让 POST 正确跳转到更新画面
- B. 在流程文件里加 `goto`，跳过 mock 的路由缺陷

**倾向 A**：因为真机上路由是对的，为迁就 mock 而加 `goto` 会污染流程文件。

**验收**：`done 44 / failed 0`

**卡住怎么办**：如果 mock 路由太复杂修不动，就用 B 并注释 `# mock 限制`

---

## 第 3 步：交互模式实测

**做什么**

```cmd
node run-flow.mjs flows/AZ-110-01-009.yaml --base http://127.0.0.1:10083
```

故意制造失败（改错一个 selector），验证 6 个交互键都能用：
`Enter` 重试 / `s` 跳过 / `v` 手填 / `k` 保留浏览器 / `q` 退出 / `a` 全停

**验收**：`k` 之后浏览器确实不关，人能继续操作

**卡住怎么办**：`readline` 在 Windows 下可能有回车问题 → 改用 `process.stdin` 逐字节读

## 第 4 步：再做 4 本，验证格式普适性

**选哪 4 本**（覆盖不同结构）

| case | 类型 | 验证什么 |
|---|---|---|
| `AY-120-01-001` | 更新系，多次弹窗 | 同一弹窗反复进出 |
| `AZ-310-01-001` | 另一条业务线 | 画面集不同 |
| `AZ-200-03-001` | 异常系（会话超时） | 无字段，纯断言 |
| `AZ-150-11-001` | 批处理 | **应该识别为「不进浏览器」** |

**验收**：4 本都能编译且 0 error；批处理本被正确标为非浏览器

**卡住怎么办**：如果格式要改，**现在改**——改完这 4 本验证，再进第 5 步

---

## 第 5 步：批量生成 450 本

**前置**：第 4 步确认格式不再变

**做什么**
1. 写 `tools/gen_flows.py`：读手顺 JSON → 生成 `flows/<CASE>.yaml`
2. **不能全自动**：AI 逐本读手顺，产出带 `row` 的步骤，人抽检
3. 分批：每批 20-30 本，跑通再下一批

**验收**：450 个 yaml，`compile_flow` 全部 0 error

**卡住怎么办**：某类本结构特殊 → 单独归一类，不要硬塞进通用格式

---

## 第 6 步：现场交互打磨

**做什么**（真机经验驱动，不在 mock 上空想）

- 失败时自动截图 + 记录当时的 DOM 片段
- `k` 保留后，提供一个「事后补记」命令：把人工做过的步骤写回 yaml
- 断点续跑：`--from-row 32`

**验收**：真机上遇到 3 种没预见的失败，都能通过交互解决

---

## 第 7 步：和旧体系对照

**做什么**
- 用 `runner.mjs`（旧）和 `run-flow.mjs`（新）跑同一本
- 逐块对比结果，记录差异

**为什么**：用户要求"之前的自动化不能浪费"。252 个积木作为模板库的可靠性，需要这个对照来证明。

**验收**：差异清单写进 `docs/rpa/07-DIFF.md`

---

## 优先级建议

如果时间有限，**0 → 1 → 2 → 3** 是必须的（能跑一本完整的）。

第 4 步之后的 450 本迁移，**建议等真机验证过 3-5 本再做**——
否则格式一改，450 本全废。
