# 旧积木 vs 新内核：一页对照

> 2026-10-27。目的：说明为什么保留旧积木、但不沿用它做执行单位。

## 结论先说

旧体系的**本体论是对的**：它已经把自动化拆成「画面 / 操作 / 验证 / 证据」。
错的是**分解粒度**：把「一段可复用的操作序列」当成积木，导致
一本手顺要跨 10 个积木、16 个 selector 文件、9 个 params 文件，
改一处要穿四层，而且积木里塞了 `force`、固定 sleep、正则分类这些
「让它看起来能跑」的东西。

新内核不否定旧积木，只把它降级为**模板片段库**：
新流程直接写 17 个原语；旧积木只在需要对照/回退时查。

## 实测数字（旧体系）

| 指标 | 数值 | 含义 |
|---|---|---|
| 积木 | 252 | 真正的「块」 |
| 只被 1–2 本用 | 125 | 一半是手顺化石，不是积木 |
| live-verified | 4 | 真机验证过的只有 4 个 |
| 无前置条件 | 240 / 252 | 大多数块没有「什么时候能用」的约束 |
| `force` 使用 | 184 次 | 绕过 disabled/可见性 |
| `goto` 使用 | 213 次 | 跳过界面，直接跳 URL |
| 「全通过」的 450 本 | 全部 mock-only | 没有业务真值 |

## 对照表

| 旧概念 | 新内核 | 处理 |
|---|---|---|
| 积木（一段操作序列） | 单步原语 + 画面链 | 不再合成；片段留作参考 |
| `force` 点击 | `click` 前置「可见可用」 | 废除；不可用就带行号报错 |
| 固定 sleep | `waitUntil(condition)` / 画面码等待 | 废除；只等条件 |
| 正则从 note 判「人工/非浏览器」 | 显式 `manual` / `externalIs` | 废除；用字段 |
| `goto` 跳页 | `goto` 必须写 `reason` | 保留但收紧 |
| 画面名 → selector 散落多处 | `ui-dictionary` + `ui-screens` + 手维护 overlay | 收拢成三层 |
| 参数写死在块里 | `values` 五种来源（literal/env/case/sys/prev） | 值可追溯 |
| mock 绿 = 通过 | mock 只证明操作链；报文/DB 记 pending | 不许假绿 |
| 一个块一个「前置条件」正则 | step 的 `on` + 编译器画面链校验 | 前置条件变成结构 |

## 借过来的东西

1. **画面码/URL 规则**：旧 `screen-rules` 里的 AMAxx/ANAxx 映射，直接用于 `ui-screens.json`。
2. **截图/DOM 捕获**：旧 runner 的证据机制（sha 去重、失败截图）保留并强化。
3. **验证类型词汇**：遷移/表示/出力(画面HC/ポップアップMsg/DL) 映射到 6 个断言原语。
4. **block-selectors 里的真机 selector**：作为 `ui-rowfields.json` / 字典的线索，不直接执行。

## 不借的东西

- n-gram 挖掘 + DP 合成（`build_blocks.py`）：它优化覆盖率，不优化正确性。
- 块级前置条件正则：容易把「看起来像」当成「能用」。
- `force` / 固定 sleep / 运行时猜控件：违反内核红线。

## 迁移顺序

1. 新本一律写 YAML（1 本 = 1 文件）。
2. 旧积木不删，作为「这段大概长什么样」的参考。
3. 遇到旧积木里 live-verified 的片段，用新内核重写并跑 mock；
   真机通过后，才把它标成可复用。
4. 450 本批量生成等格式冻结后再做。
