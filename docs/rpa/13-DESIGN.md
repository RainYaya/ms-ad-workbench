# 13 — 设计（四轮追问后的定稿）

> 2026-10-27。词汇以 `GLOSSARY.md` 为准。
> 这份文档回答一个问题：**为什么现在的 RPA 不够定制，改成什么样才算够。**

## 0. 一句话

把手顺的 19,056 行操作收敛成 **452 条绑定规则**，让控件、绑定、值、流程各自只有一个主人；
人只需要在 Studio 里对着**真实画面**确认约 220 条绑定，1,371 本就自动跟着对。

## 1. 现在为什么不够定制

三处断裂，都是"换 YAML 时把控件层丢了"造成的：

| 断裂 | 现在 | 后果 |
|---|---|---|
| 手顺措辞 ↔ 控件 | 精确匹配 + 别名 + **模糊兜底** | 找不到就 `pendingRuntime`；模糊命中时是**猜** |
| 控件 ↔ 前端 | 字典只收了 85 输入框 / 295 按钮 | 146 勾选框、31 单选、22 多行文本、17 链接**根本不在库里** |
| 人 ↔ 流程 | Studio 是表单 + 下拉列表 | 看不到画面，无法"点着控件改"，只能手写标签 |

## 3. 四层真源

| 层 | 内容 | 谁说了算 | 共享范围 | 文件 |
|---|---|---|---|---|
| 手顺行 | 顺序、意图、期望、Excel 行号 | 手顺数据，只读 | 每本独立 | `v2/data/cases/*.js` |
| 控件库 | 每个控件的 id/name/type/selector/行模板 | 真实 HTML，自动挖 + 人工确认 | 全部 | `ui-controls.json` |
| 绑定表 | 措辞 → 控件 | 人确认，带证据 | 全部 | `flows/bindings.yaml` |
| 本别覆盖 | 真正的例外 | 人，必须写理由 + 行号 | 一本 | `flows/overrides/<本>.yaml` |

**冲突时谁赢**：层越靠下越具体。本别覆盖 > 绑定表 > 控件库 > 手顺（仅限"怎么做"，"做什么"永远以手顺为准）。
**任何一层都不允许改期望。**

## 4. 两种身份

| | 本（试验流程） | 自建流程 |
|---|---|---|
| 来源 | 手顺派生 | 人在 Studio 里画 / 从本 fork |
| 行号 | 每步必须有 | 无 |
| 期望 | 来自手顺，禁改 | 自定 |
| 算结合试验结果 | 算 | **不算** |
| 位置 | `flows/books/<本>.yaml` | `flows/custom/<名>.yaml` |

共用引擎、控件库、绑定表。报告里永不混算。
生成器只写 `flows/books/`；`flows/custom/` 永远不碰。

## 5. 绑定层

三种显式形式，**没有任何一种会猜**：

1. **模板**（确定性查找，命中数必须恰为 1，否则报错 + 行号）
   - `「X」押下` / `「X」クリック` → 该画面标签恰为 X 的按钮/链接
   - `X`（输入行）→ 该画面标签为 X 的输入控件
   - `「X」入力` → 同上
2. **指令**（措辞本身就是动作，不指向单个控件）
   - `各項目に入力` / `画面各項目入力` → `fillAll`，值来自別紙数据
   - `「No.」リンク...` / `No` → `chooseRow`，锚点值来自本数据
3. **显式绑定**：前两种覆盖不了的，一条一条钉死，写进绑定表

每条解析都记录 `{row, screen, phrase, rule, control}`，可回溯。
**模糊匹配（≥60% 重叠）删除**，它违反"不许猜"。

## 6. 控件库 v2

- 来源：`reference/webapps/<APP>/webapp/WEB-INF/views/<CODE>.html`（cp932）
- 覆盖全部可交互元素，不再只看 `field_title/field_value` 成对结构
- 每个控件：`{key, label, kind, id, name, type, selector, rowScope, status}`
- 行内控件：JSP `${stat.index}` 这类模板不展开成具体元素，标成 `rowScope: true` + `namePattern`
- 与 mock 对照：mock 里不存在的 id 标 `mockMissing`（说明 mock 落后于真实前端）
- `status`: `mined`（自动）/ `confirmed`（真机看过）/ `stale`

## 7. Studio

| 面板 | 内容 |
|---|---|
| 左：本 | 列表，按画面覆盖/状态分组；显示 L0/L1/L2 |
| 中：画布 | 组件面板（17 原语）+ 步骤卡；本里每步显示行号 |
| 中上：**画面面板** | 渲染 mock 页；悬停高亮控件；点击 = 绑定到当前步骤 |

| 右：数据 | 值表（来源/行/备注） |
| 下：运行 | 日志 / 证据 / 检查；失败时弹 5 选项（重试/跳过/手填/接管/中止） |
| 新：绑定复核 | 220 条待确认，一次一条，显示手顺原文 + 候选控件高亮 + 影响多少行 |

## 8. 组件

- 定义：原语 + 参数组成的命名序列，存 `components/*.yaml`
- 只允许顺序原语，**禁止分支/循环，禁止新原语**
- 在自建流程里直接用
- 在本里只能用"展开后每步仍能指回具体行号"的组件；做不到就拒绝
- 组件自身记录覆盖的行区间

## 9. 本别覆盖

```yaml
# flows/overrides/AZ-110-01-009.yaml
book: AZ-110-01-009
overrides:
  - row: 32
    do: manual
    reason: "手顺要求更新后确认状态，页面未跳转；结合试验按人工确认处理"
```

允许的动作只有：`skip` / `manual` / `capture` / `valueFrom` / `binding`。
出现 `expect` 或 `expected` 直接拒绝生成。

## 10. 判据

| 级 | 判据 | 范围 |
|---|---|---|
| L0 | 编译 0 error；0 条未确认绑定；步骤数 = 手顺操作行数 | 全部本 |
| L1 | mock 全行 done；`evidencePolicy: all`；0 fail | 全部本 |
| L2 | 每个画面至少 1 本真机跑通，证据入档 | 每个画面 |

- 画面无 HTML 的本（约 9%）**不生成**，进"未覆盖清单"
- mock 绿但该画面未做 L2 → 报告标黄，不算完成

## 11. 失败协议

终端已有 `[Enter]retry [s]skip [v]manual value [k]takeover [q]quit`。
Studio 目标形态：runner 暴露本地控制通道，失败时暂停、浏览器不关，
Studio 弹同样五选项；M1–M3 期间 Studio 用 `--yes` 只记录。

失败记录必须含：`row` / `screen` / `phrase` / `expected` / `actual` / `url` / 截图 / 手顺原文。

## 12. 施工顺序

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M1 | 控件库 v2（62 页全类型） | 真实 HTML 每个可交互元素都有条目；mock 对照无假缺失 |
| M2 | 452 条绑定候选 + 删模糊匹配 | 全 1,371 本编译 0 静默猜测；未确认 → 阻塞 |
| M3 | 第一刀 6 画面（ANA11/AMA13/AMA15/AMA18/AMA03/ANA10）复核 | 41 条绑定确认；684 本 L0 通过 |
| M4 | 身份 + 覆盖 + L0/L1 报告 | `books/` 与 `custom/` 分离；overrides 生效 |
| M5 | 组件 | 自建流程可用组件；本里组件保留行号 |
| M6 | 批量生成 + 报告 | 1,114 本生成；未覆盖清单成文 |

第一刀数字：6 画面 / 5,558 操作行 / 41 条绑定 / 684 本。

## 13. 不做什么

- 不加第 18 个原语
- 不做分支/循环（本里用 `requires` 停，不用 if）
- 不猜 selector，不用 force，不用固定 sleep
- 不改期望让流程通过
- 不把 mock 绿当成完成
- 不手改 `execution-status.json`
