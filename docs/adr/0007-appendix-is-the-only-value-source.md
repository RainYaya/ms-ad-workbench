# 0007 — 值是别紙【操作内容】的原文，生成器不做任何补全

**Status**: accepted

手顺正文只写「画面各項目入力」「【別紙】操作内容 1 参照」；具体值在别紙的表格里。生成器读取别紙的 OPERATION / DISPLAY 页，把 `{block, label} → value` 原样搬进 flow 的 `values`，并在 `fillAll` 的 `use` 列表里按别紙的行序列出标签。

别紙的列位置不固定（OPERATION 的标签列是 2、值列是 11；DISPLAY 是 1 和 12，同一个工作簿里也可能变），所以列不写死，按"表头列之后的众数非备注列"检测。块号在每张画面上会从 1 重新开始，因此不能用 `operationNo` 直接索引块：**优先取块号相同且所有标签都存在于当前画面的块；否则取第一个未使用且标签全部存在的块**。这就是"值来自别紙、控件来自绑定表"的边界。

规则：

- 别紙里没有的值 → 阻塞该本，不设默认值，不沿用上一块。
- 别紙标签在画面上不存在 → 查绑定表；绑定未确认 → 阻塞并给出规则 id（`B0123 needs-human`），不静默跳过。
- 同一标签在一本内出现不同值 → 值写在 `use` 的条目上，不污染共享的 `values`。
- 别紙【表示内容】尚未实现逐项断言 → 写成 `expect.ref {status: unresolved}`，检查器报 `PENDING`，**不当作通过**。

**Considered Options**

- 从画面反填默认值：会在测试里制造"通过"，等于篡改试验数据。
- 让 LLM 读别紙：不可复现，违反"运行时不许猜"。

**Consequences**

- 1,371 本中 122 本只靠 auto/confirmed 绑定即可生成并通过 L0；其余按"缺哪个别紙标签/哪条绑定未确认"逐本列出。
- 别紙值变化时重跑生成器即可，无需改代码。
- 未实现的表示内容断言会一直显示为 PENDING，直到实现逐字段比对。
