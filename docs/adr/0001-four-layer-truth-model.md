# 0001 — 四层真源：手顺行 / 控件库 / 绑定表 / 本别覆盖

**Status**: accepted（取代 `docs/rpa/00-DECISIONS.md` D3 的「三层结构」）

一本流程里的事实原来混在一个 YAML 里，出错时说不清是手顺写错了、字典缺控件、还是绑定找错了人。我们把它拆成四层，每层只有一个主人：手顺行（只读，来自手顺数据）、控件库（来自真实 HTML，自动挖）、绑定表（人工确认，跨本共享）、本别覆盖（单本例外，必须写理由）。按具体程度决胜：覆盖 > 绑定 > 控件库；「做什么」永远以手顺为准，「怎么做」以下层为准。任何一层都不得修改期望。

**Considered Options**

- 保持单一 YAML：改一处穿四层，1,371 本无法定位责任。
- 只拆出控件库、不拆绑定表：绑定逻辑继续散落在编译器里，无法审计"这条规则凭什么命中"。

**Consequences**

- 新增 `ui-controls.json` 与 `flows/bindings.yaml` 两个一等文件。
- 编译器从"查字典 + 模糊"变成"查绑定表 + 模板 + 报错"。
- 一次绑定修正影响全部本，而不是逐本改。
