# capture.mjs — 実機 DOM 抓取器

## これは何

真机のブラウザを人が操作するだけで、**画面ごとの DOM を全部残す**ツール。
目的は「セレクタを推測しないこと」。実物を取ってから決める。

手順書の 6 つの未解決項目（表内の動的フィールド、JS で挿入される検索結果）は、
テンプレート HTML を見ても絶対に分からない。実機の DOM を見るしかない。

## 使い方

```cmd
cd automation\node-runner

node capture.mjs --url https://実機ホスト/AMB/AMA01.html --out capture-20261027 --edge
```

ブラウザが開く。あとは**普通に手で操作する**。

- ログインが必要なら画面で手でログインする（認証情報は一切預からない）
- 画面が変わる / ポップアップが開く / 操作が 1.5 秒止まる → 自動で保存
- 終わったら `Ctrl+C`

## 何が残るか

```
capture-20261027/
  index.json              全ページ一覧（順番・URL・タイトル・件数）
  pages/
    001_申込書品質管理メニュー画面.html     ← レンダリング後の実 DOM
    001_....json                          ← 抽出済み構造（id/ラベル対応/表の行）
    001_....png                           ← 画面
    002_...
```

`.json` の中身が重要:

```json
{
 "url": "...", "title": "...", "charset": "Shift_JIS",
 "ids": [...],                  // 全 id
 "names": [...],                // 全 name（動的 name の実物がここに入る）
 "pairs": [{label, id, tag}],   // ラベル → 要素
 "buttons": [{label, id, disabled}],
 "tables": [{th, sampleRows, rowCount}],   // ← rowfield を解く鍵
 "bodyText": "..."
}
```

## 終わったら

`capture-20261027` フォルダを丸ごと送ってくれれば、こちらで:

1. `tools/build_ui_dictionary.py --src capture-.../pages` で辞書を実物から再生成
2. 6 つの未解決項目（row 34/39/42/43/45/48）を実 DOM から確定
3. `ui-screens.json` の `inferred` 25 件を `confirmed` に更新

## 注意

- **認証情報は渡さない**。ログインは自分で画面からやる
- 1 画面あたり最大 4 回までしか保存しない（同じ画面の連打対策）
- `--max 400` で上限。超えたら古いのから止まる
- `--headless` はテスト用。実機では付けない（見えないと操作できない）
- HTTPS 証明書が自己署名でも通す（`ignoreHTTPSErrors`）

## どの画面を操作すればいいか

全部やる必要はない。**今詰まっている 6 項目に関係する画面だけでいい**:

| 画面 | なぜ |
|---|---|
| 不備内容入力画面－新規（AMA03） | 項目名検索を開く導線 |
| 項目名検索画面（AMA13） | **row 39**: 検索結果の行が JS 挿入。行選択の selector が不明 |
| 不備内容入力画面-更新（AMA04） | **row 34/42/43/48**: 表内の検索/チェック/修/照会区分 |
| 照会内容編集画面（AMA15） | **row 45**: 入力欄が JS 生成 |
| 募集人検索画面（AMA18） | 確認用（ここは既に解析済み） |

つまり **009 を 1 回最後まで手で流す**だけで、6 項目のうち 5 項目が埋まる。
